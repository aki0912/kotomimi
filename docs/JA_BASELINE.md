# Japanese ASR Baseline (PR 0)

This document freezes the evaluation procedure before any Japanese recognition,
VAD, model-selection, or CLI-default changes.

## Evaluation design

`scripts/eval_ja_streaming.py` reads one JSONL manifest and evaluates every
entry through the same four named paths:

- `offline_primary`: the complete clip is decoded directly by the existing
  ReazonSpeech recognizer.
- `stream_fast`: the existing balanced pipeline, production Silero VAD, and
  fast final output, without the Refiner result.
- `stream_refine`: the same balanced VAD pipeline, scored from Refiner output
  when available (otherwise its fast final fallback).
- `stream_single_ja`: the VAD fast path equivalent to
  `--mode single --lang ja`.

Relative WAV paths are resolved from the manifest directory. Required JSONL
fields are `id`, `wav`, `text`, and `category`; optional fields are `terms`,
`digits`, `speaker_group`, `license_source`, and `notes`.

Example:

```json
{"id":"ja_clean_001","wav":"ja_clean_001.wav","text":"今日は東京都多摩市で会議をします。","category":"clean_mic","terms":["東京都多摩市"],"digits":[]}
```

Run:

```bash
python scripts/eval_ja_streaming.py \
  --manifest testdata/eval_ja/manifest.jsonl \
  --output artifacts/ja_eval/current
```

The output directory contains `metrics.json`, `hypotheses.jsonl`, and
`report.md`. Metrics use NFKC normalization with punctuation and whitespace
removed. CER is micro-averaged. Leading/trailing missing counts only count an
optimal alignment that begins/ends with a reference deletion. Term precision
uses the manifest-wide term vocabulary, and digit exactness compares the
ordered digit strings declared by `digits`. Hypothesis rows label
`offline_primary` output as `text_stage=raw`; streaming rows are explicitly
`text_stage=display` and set `raw_text` to null because the current runtime API
does not expose the pre-punctuation text. The evaluator never fabricates raw
text from display text.

## Measured broadcast baseline

Measured on 2026-08-29 using 15 ReazonSpeech test-split broadcast clips
generated by `scripts/make_realset.py` (85.592 seconds of Japanese audio).
The command above ran with 4 threads, accelerated WAV input (no real-time
pacing), `min_silence=0.35`, and `max_speech=12.0`. The installed
`scripts/download_models.py --minimal` model set contains ReazonSpeech,
whisper-tiny LID, Silero VAD, and the fp32 Japanese punctuation model. It does
not contain SenseVoice, so the balanced streaming paths explicitly used the
existing missing-SenseVoice fallback. Results are stored in
`artifacts/ja_eval/reviewed` locally and are not committed.

| path | CER | S / D / I | leading / trailing missing | RTF | p50 / p95 final | empty |
|---|---:|---:|---:|---:|---:|---:|
| `offline_primary` | 6.87% | 13 / 6 / 1 | 1 / 1 | 0.0093 | 52 / 76 ms | 0.00% |
| `stream_fast` | 14.78% | 11 / 20 / 12 | 2 / 3 | 0.0297 | 90 / 165 ms | 6.67% |
| `stream_refine` | 14.09% | 10 / 20 / 11 | 2 / 3 | 0.0447 | 82 / 138 ms | 6.67% |
| `stream_single_ja` | 14.78% | 11 / 20 / 12 | 2 / 3 | 0.0152 | 49 / 91 ms | 6.67% |

This is a small, broadcast-only baseline rather than a representative Japanese
accuracy claim. It contains no annotated term list, so term metrics are not
available. Digit exactness is 0% because all five clips containing Arabic
digits in the references were emitted with kanji numerals; the metric
intentionally treats that formatting change as non-exact.

The latency columns measure decode-to-final work after VAD emits a segment;
they do not include real-time audio pacing or the configured silence duration.
RSS is process-wide for the shared evaluator and peaked at about 1080 MiB; it
is not an isolated per-model allocation measurement.

`metrics.json` records the OS, machine, Python and sherpa-onnx versions, model
directory names, manifest SHA-256, and Silero VAD SHA-256 alongside the
settings. Keep generated reports under `artifacts/`; models and evaluation
audio remain outside Git.
